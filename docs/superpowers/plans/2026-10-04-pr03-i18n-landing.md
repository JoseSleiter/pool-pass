# PR 03 — i18n de landing y /reservar (ES | EN) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Añadir i18n sin librerías a la landing y a `/reservar` (español por defecto, inglés con un selector `ES | EN`), sacando todos los textos visibles a diccionarios tipados, sin cambiar nada de lo que hoy ve un usuario en español.

**Architecture:** `src/lib/i18n/es.ts` es la fuente de verdad; `Dictionary = typeof es` y `en.ts` se tipa como `Dictionary`, así que el compilador rechaza claves faltantes o sobrantes a cualquier profundidad. El idioma vive en la cookie `pp_lang`; el servidor lo lee con `getLocale()` (async, `cookies()` de Next 16), el root layout pone `<html lang>` y envuelve la app en `<I18nProvider locale dict>`. Los Server Components reciben el diccionario como prop `t`; los Client Components usan `useT()` / `useLocale()`. El selector llama a la server action `setLocale()` y luego `router.refresh()`.

**Tech Stack:** Next.js 16.2 App Router (`cookies()` async, server actions), React 19 (`<Context value>`, `useTransition` async), TypeScript estricto, date-fns 4 (`es` / `enUS`), react-day-picker 10, Vitest 4 + Testing Library (jsdom por archivo), Playwright (Pixel 7).

## Desviaciones del roadmap

El contrato §3.3 se respeta en lo esencial (sin librería, cookie `pp_lang`, `getLocale()`, `getDictionary()`, `<I18nProvider dict locale>`, `useT()`, `setLocale()` + `router.refresh()`, date-fns `es`/`enUS`, zona `America/Caracas`). Lo que cambia o se precisa:

1. **Más archivos que `{types, es, en, index}`.** `index.ts` importa `next/headers` y `server-only`, así que no puede importarse desde un Client Component. Se añaden en `src/lib/i18n/`: `provider.tsx` (cliente: `I18nProvider`, `useT`, `useLocale`), `format.ts` (`interpolate`, `formatParty`), `date-locale.ts` (`dateFnsLocale`), `validation.ts` (issue de zod → clave del diccionario) y `booking-errors.ts` (resultado del servidor → texto). La server action vive en `src/app/actions/locale.ts`, junto a `booking.ts`.
2. **El diccionario solo contiene strings.** Cruza la frontera servidor→cliente como prop del provider, así que no puede tener funciones. Las variables se escriben `{nombre}` y se rellenan con `interpolate()`. Los plurales de "adulto/niño" usan claves `adultOne`/`adultOther`, etc.
3. **Los Server Components no usan `useT()`** (los hooks no existen en RSC): `SiteHeader`, `SiteFooter`, `Hero`, `Features`, `HowItWorks` y `FinalCta` reciben `t: Dictionary` como prop desde la página.
4. **`router.refresh()` es redundante en Next 16** (según `node_modules/next/dist/docs/01-app/01-getting-started/07-mutating-data.md` §Cookies, poner una cookie en una server action ya vuelve a renderizar la página). Se mantiene igual porque lo pide el contrato y no hace daño.
5. **`<html lang>` se decide en el root layout, que también envuelve al admin.** Si alguien del staff eligió EN en la landing, el admin (solo español) saldría con `lang="en"`. Se acepta: separar root layouts con route groups queda fuera de alcance. Además, leer la cookie en el root layout vuelve dinámicas todas las rutas (casi todas ya lo eran: `force-dynamic` o protegidas por sesión).
6. **`src/lib/schemas.ts` no se toca** (el servidor lo usa, el email está en español). El cliente traduce los issues de zod por campo y código con `validationKey()`. Los textos en español del diccionario son idénticos a los del schema (lo comprueba un test). Las únicas diferencias visibles en español están en caminos que el schema no personaliza: un nombre de más de 60 caracteres o una clave de más de 12 pasan de mostrar el mensaje por defecto de zod, en inglés ("Too big: …"), a "Demasiado largo".
7. **Mensajes del servidor.** `payment_pending`, `rate_limited` y `rate_unavailable` se muestran desde el diccionario (en español, texto idéntico al del servidor). `validation` muestra "Datos inválidos" en vez del mensaje del servidor: el cliente valida antes con el mismo schema, así que solo llega por el honeypot, que ya devolvía "Datos inválidos". En `payment_declined`, el motivo que manda el banco (`result.message`, de Mercantil) sigue en español dentro de la plantilla en inglés: no se puede traducir.
8. **`landingContent.steps` y `landingContent.amenities` pasan a ser `{ icon, id }`.** El texto sale de `t.content.steps[id]` / `t.content.amenities[id]`, y `tagline`, `subtitle` y `hours` se mueven al diccionario. `clubName`, `address`, `whatsapp` e `instagram` se quedan en `landing-content.ts` porque no se traducen, y el email y el logo los siguen usando.
9. **`src/app/manifest.ts` no se traduce**: el manifest no depende de la petición. Queda fuera.
10. **Conflicto con el PR 00** (misma ola): el PR 00 cambia la línea `address` de `landing-content.ts`. La Task 12 indica cómo conservar el valor que tenga `develop`.

**Preguntas abiertas para el dueño:** (a) Revisar el inglés de `en.ts`, sobre todo los términos locales: se dejó "Pago Móvil", "C2P", "BCV" y "Bs." sin traducir porque son nombres propios del medio de pago. (b) ¿Se quiere `lang` correcto también en el admin? Eso implicaría un layout raíz propio para `/admin`.

```ts
import { describe, it, expect } from 'vitest';
import { es } from './es';
import { en } from './en';
import { isLocale, LOCALES, DEFAULT_LOCALE, LOCALE_COOKIE } from './types';

/** Flattens a nested dictionary into { 'a.b.c': 'value' }. Non-string leaves are a bug. */
function leaves(obj: unknown, prefix = ''): Record<string, string> {
  const out: Record<string, string> = {};
  for (const [key, value] of Object.entries(obj as Record<string, unknown>)) {
    const path = prefix ? `${prefix}.${key}` : key;
    if (typeof value === 'string') out[path] = value;
    else if (value !== null && typeof value === 'object') Object.assign(out, leaves(value, path));
    else throw new Error(`${path} must be a string or a nested object, got ${typeof value}`);
  }
  return out;
}

function placeholders(s: string): string[] {
  return [...s.matchAll(/\{(\w+)\}/g)].map((m) => m[1]).sort();
}

const esLeaves = leaves(es);
const enLeaves = leaves(en);

describe('dictionaries', () => {
  it('flattens nested keys (sanity check of the helper)', () => {
    expect(leaves({ a: { b: 'x', c: { d: 'y' } } })).toEqual({ 'a.b': 'x', 'a.c.d': 'y' });
  });

  it('en has exactly the same nested keys as es', () => {
    expect(Object.keys(enLeaves).sort()).toEqual(Object.keys(esLeaves).sort());
  });

  it('has no empty strings', () => {
    for (const [path, value] of Object.entries({ ...esLeaves, ...enLeaves })) {
      expect(value.trim(), path).not.toBe('');
    }
  });

  it('uses the same {placeholders} in both languages', () => {
    for (const path of Object.keys(esLeaves)) {
      expect(placeholders(enLeaves[path]), path).toEqual(placeholders(esLeaves[path]));
    }
  });

  it('en is actually translated (no value copied verbatim from es)', () => {
    const copied = Object.keys(esLeaves).filter((p) => esLeaves[p] === enLeaves[p]);
    expect(copied).toEqual([]);
  });
});

describe('locale constants', () => {
  it('supports es and en with es as default and pp_lang as cookie', () => {
    expect(LOCALES).toEqual(['es', 'en']);
    expect(DEFAULT_LOCALE).toBe('es');
    expect(LOCALE_COOKIE).toBe('pp_lang');
  });

  it('isLocale accepts only the supported codes', () => {
    expect(isLocale('es')).toBe(true);
    expect(isLocale('en')).toBe(true);
    for (const bad of ['EN', 'fr', '', undefined, null, 1]) expect(isLocale(bad)).toBe(false);
  });
});
```

```ts
import type { es } from './es';

/** Supported UI languages. Spanish is the default and the source dictionary. */
export const LOCALES = ['es', 'en'] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = 'es';

/** Cookie that stores the visitor's language choice. Routes carry no locale prefix. */
export const LOCALE_COOKIE = 'pp_lang';

/** Shape of every dictionary: es.ts is the source; en.ts must match it exactly. */
export type Dictionary = typeof es;

export function isLocale(value: unknown): value is Locale {
  return typeof value === 'string' && (LOCALES as readonly string[]).includes(value);
}
```

```ts
import type { Dictionary } from './types';

/** Replaces `{name}` tokens with values from `vars`; unknown tokens are kept as-is. */
export function interpolate(template: string, vars: Record<string, string | number>): string {
  return template.replace(/\{(\w+)\}/g, (match, key: string) =>
    vars[key] !== undefined ? String(vars[key]) : match
  );
}

/** "2 adultos, 1 niño" / "2 adults, 1 child" — omits zero groups, like partyLabel(). */
export function formatParty(party: Dictionary['party'], adults: number, children: number): string {
  const parts: string[] = [];
  if (adults > 0) {
    parts.push(interpolate(adults === 1 ? party.adultOne : party.adultOther, { count: adults }));
  }
  if (children > 0) {
    parts.push(interpolate(children === 1 ? party.childOne : party.childOther, { count: children }));
  }
  return parts.join(', ');
}
```

```ts
function capitalizeTokens(s: string): string {
  // Same reasoning as visitLabelEs: split on spaces, not \b, so accented
  // weekdays ("sáb", "mié") are capitalized correctly.
  return s
    .split(' ')
    .map((w) => w.charAt(0).toUpperCase() + w.slice(1))

}
```

```ts
import type { Dictionary } from './types';

export type ValidationKey = keyof Dictionary['validation'];

/** Minimal shape of a zod issue: we only need the field and the issue code. */
export interface IssueLike {
  path: readonly PropertyKey[];
  code: string;
}

/**
 * Maps a paymentSchema issue to a dictionary key. The schema keeps its Spanish
 * messages (the server and the email use it); the client shows the translated
 * text for the same failure instead.
 */
export function validationKey(issue: IssueLike): ValidationKey {
  switch (String(issue.path[0])) {
    case 'date':
      return 'invalidDate';
    case 'firstName':
    case 'lastName':
      return issue.code === 'too_big' ? 'tooLong' : 'required';
    case 'email':
      return 'invalidEmail';
    case 'idType':
      return 'invalidIdType';
    case 'idNumber':
      return 'idDigits';
    case 'phone':
      return 'invalidPhone';
    case 'bankCode':
      return 'bankRequired';
    case 'otp':
      return issue.code === 'too_big' ? 'tooLong' : 'pinRequired';
    case 'adults':
      return issue.code === 'custom' ? 'noAttendees' : 'invalid';
    default:
      return 'invalid';
  }
}
```

```ts
import type { BookingResult } from '@/lib/booking/process';
import type { Dictionary } from './types';
import { interpolate } from './format';

/** A failed submit, plus the client-only "nobody attending" guard. */
export type SubmitFailure =
  | Extract<BookingResult, { ok: false }>
  | { ok: false; error: 'no_attendees' };

/**
 * Text for a failed submit, in the current language. Stored failures (not
 * strings) are rendered through this, so switching language re-translates an
 * error that is already on screen.
 */
export function submitErrorMessage(failure: SubmitFailure, t: Dictionary): string {
  switch (failure.error) {
    case 'no_attendees':
      return t.errors.noAttendees;
    case 'capacity':
      return interpolate(t.errors.capacity, { remaining: failure.remaining });
    case 'payment_declined':
      // The reason comes from the bank and cannot be translated.
      return interpolate(t.errors.paymentDeclined, { message: failure.message });
    case 'payment_pending':
      return t.pending.message;
    case 'rate_limited':
      return t.errors.rateLimited;
    case 'rate_unavailable':
      return t.errors.rateUnavailable;
    case 'validation':
      return t.errors.invalidData;
  }
}
```

```ts
import { es } from './es';
```

```ts
import { DEFAULT_LOCALE, LOCALE_COOKIE, isLocale, type Dictionary, type Locale } from './types';

const dictionaries: Record<Locale, Dictionary> = { es, en };

/**

export async function getLocale(): Promise<Locale> {
```

```ts
'use server';

import { cookies } from 'next/headers';
import { LOCALE_COOKIE, isLocale, type Locale } from '@/lib/i18n/types';

const ONE_YEAR_SECONDS = 60 * 60 * 24 * 365;

/**
 * Persists the visitor's language. Setting a cookie in a server action makes
 * Next 16 re-render the current route; the caller still runs router.refresh()
 * (roadmap §3.3).
 */
export async function setLocale(locale: Locale): Promise<void> {
  // Server actions are public endpoints: never trust the argument's type.
  if (!isLocale(locale)) return;
  const store = await cookies();
  store.set(LOCALE_COOKIE, locale, {
    path: '/',
    maxAge: ONE_YEAR_SECONDS,
    sameSite: 'lax',
    httpOnly: true, // only the server reads it
    secure: process.env.NODE_ENV === 'production',
  });
}
```

```tsx
'use client';

import { createContext, useContext, useMemo, type ReactNode } from 'react';
import type { Dictionary, Locale } from './types';

type I18nValue = { locale: Locale; t: Dictionary };

const I18nContext = createContext<I18nValue | null>(null);

/**
 * Mounted once in the root layout with the dictionary picked on the server.
 * After setLocale() + router.refresh() the layout re-renders with new props,
 * so every client component below re-renders in the new language without
 * losing its state.
 */
export function I18nProvider({
  locale,
  dict,
  children,
}: {
  locale: Locale;
  dict: Dictionary;
  children: ReactNode;
}) {
  const value = useMemo(() => ({ locale, t: dict }), [locale, dict]);
  return <I18nContext value={value}>{children}</I18nContext>;
}

function useI18n(): I18nValue {
  const ctx = useContext(I18nContext);
  if (!ctx) throw new Error('useT()/useLocale() must be used inside <I18nProvider>');
  return ctx;
}

export function useT(): Dictionary {
  return useI18n().t;
}

export function useLocale(): Locale {
  return useI18n().locale;
}
```

```tsx
/**
 * Shared calendar editor. Reports the picked day as a `YYYY-MM-DD` string and the
 * viewed month as `YYYY-MM`. Disables past days and days with no availability.
 *
 * Renders a bare, centered calendar with no surrounding chrome — callers wrap it
 * in the editor box (header + "Listo" button) so it stays homogeneous with the
 * people editor and users can close it without picking a new date.
 *
 * Month and weekday names follow the visitor's language (date-fns es / enUS).
 */
export function DatePickerPanel(props: {
  date: string;
  availability: Record<string, number>;
  onSelect: (date: string) => void;
  onMonthChange: (month: string) => void;
}) {
  const locale = useLocale();
  const anchor = new Date(`${props.date}T12:00:00`);
  return (

      <Calendar
        mode="single"
        locale={dateFnsLocale(locale)}
        weekStartsOn={0}
        className="bg-transparent [--cell-size:2.5rem]"
        selected={anchor}
        defaultMonth={anchor}
        onSelect={(d) => {
          if (d) props.onSelect(format(d, 'yyyy-MM-dd'));
        }}
        onMonthChange={(m) => props.onMonthChange(format(m, 'yyyy-MM'))}
        disabled={(d) => {
          const key = format(d, 'yyyy-MM-dd');
          const today = new Date();
          today.setHours(0, 0, 0, 0);
          if (d < today) return true;
          return props.availability[key] !== undefined && props.availability[key] <= 0;
        }}
      />
    </div>
  );
}
```

```tsx
function Field(props: {
  label: string;
  value: string;
  onChange: (v: string) => void;
  error?: string;
  type?: string;
  placeholder?: string;
  hint?: string;
  inputMode?: 'numeric' | 'tel' | 'email' | 'text';
  autoComplete?: string;
}) {
  return (
    <div>
      <label className="block rounded-xl border border-border bg-card px-4 py-2.5">
        <span className="block text-xs font-medium text-muted-foreground">{props.label}</span>
        <input
          type={props.type ?? 'text'}
          inputMode={props.inputMode}
          autoComplete={props.autoComplete}
          placeholder={props.placeholder}
          value={props.value}
          onChange={(e) => props.onChange(e.target.value)}
          className="w-full bg-transparent py-1 font-semibold text-navy outline-none placeholder:font-normal placeholder:text-muted-foreground"
        />
      </label>
      {props.error && <p className="mt-1 text-xs text-destructive">{props.error}</p>}
      {props.hint && !props.error && <p className="mt-1 text-xs text-muted-foreground">{props.hint}</p>}
    </div>
  );
}
```

```tsx
'use client';

import { useTransition } from 'react';
import { useRouter } from 'next/navigation';
import { setLocale } from '@/app/actions/locale';
import { useLocale, useT } from '@/lib/i18n/provider';
import { LOCALES, type Locale } from '@/lib/i18n/types';
import { cn } from '@/lib/utils';

/** Language names in their own language, shown as tooltips. */
const NATIVE_NAMES: Record<Locale, string> = { es: 'Español', en: 'English' };

/** "ES | EN" switch. Saves the choice in the pp_lang cookie and re-renders the route. */
export function LocaleToggle() {
  const locale = useLocale();
  const t = useT();
  const router = useRouter();
  const [pending, startTransition] = useTransition();

  function choose(next: Locale) {
    if (next === locale || pending) return;
    startTransition(async () => {
      await setLocale(next);
      router.refresh();
    });
  }

  return (
    <div role="group" aria-label={t.header.language} className="flex items-center text-xs font-bold tracking-wider">
      {LOCALES.map((l, i) => (
        <span key={l} className="flex items-center">
          {i > 0 && <span aria-hidden className="text-white/40">|</span>}
          <button
            type="button"
            lang={l}
            title={NATIVE_NAMES[l]}
            aria-pressed={l === locale}
            disabled={pending}
            onClick={() => choose(l)}
            className={cn(
              'inline-flex h-11 min-w-11 cursor-pointer items-center justify-center rounded-md transition-colors disabled:cursor-wait',
              l === locale ? 'text-white' : 'text-white/55 hover:text-teal-soft'
            )}
          >
            {l.toUpperCase()}
          </button>
        </span>
      ))}
    </div>
  );
}
```
